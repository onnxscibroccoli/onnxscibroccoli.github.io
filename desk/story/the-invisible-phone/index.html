Investigation 6 · Platform

Google built background phone control — for Google

Android can run apps the user is not looking at. The documented way to do it is not the accessibility tree. It is a privileged, screenshot-driven virtual device reserved for the OEM assistant.

Newsroom Desk · 9 September 2026 · See the record

There are two stacks. Journalism that collapses them will get the platform wrong.

The public stack is AccessibilityService: a user-enabled service that reads the tree and acts on the display the user is looking at. It can run as a background service. It still occupies the screen.

The privileged stack is Computer Control. Google documents it as a way for an OEM-preloaded assistant, holding ACCESS_COMPUTER_CONTROL, to run apps on a background virtual display. Third-party apps cannot hold that permission.

FLAG_SECURE blocks screenshots. It does not hide a view from the accessibility tree. The tree-side control in Android 16 is accessibilityDataSensitive.

There is, in the public API surface, no general, root-free, provider-agnostic way for a third-party agent to operate Android without occupying the user’s screen. That is a verified absence, not a dare.
