Open-source work on autonomous vehicles, robotics, and the security tools around them is scattered. The useful repositories are not all in one company or one country. Some of them are hard to read if you do not read the language of the README and the comments.

This digest is a target list and a design for a pipeline: watch a short list of hosts, translate documentation without touching executable syntax, and keep an English fork that a person reviews. It is a working brief dated 14 October 2026. It is not a statement that a state runs any of these projects, and it is not a statement that every maintainer lives in the country on the tag.

Tags are intake labels. Verified means a public repository or model card was checked for this edition. Cited means the source brief named it and this pass did not re-confirm the tree. A vector is a capability with no repository attached.

Where the work actually sits

Jurisdictions

China

Embodied agents and camera-first perception

The verified anchor is HorizonRobotics/HoloAgent: one agent loop that plans, calls robot skills, and keeps a 3D spatial memory instead of treating navigation and manipulation as separate demos.

The brief also points at Fast-BEV for multi-camera 3D detection and at GAAS for VTOL and UAV software. Both stay cited until someone opens the tree, the license, and the last commit.

What is worth copying is the pattern, not a slogan about a country: camera-first geometry, then a closed loop that can recover when a skill only half-finishes.

Japan

Certifiable stacks and zero-copy middleware

Autoware is the modular ROS 2 baseline: perception, behavior, and control with a real release process. Agnocast sits under it and moves large sensor payloads between processes without serializing them. Nebula is the sensor-driver boundary. AutoE2E is the map-optional neural trajectory model.

PythonRobotics is the algorithm reference used to check whether a new planner is actually a new idea.

Hayabusa moves into this column. It is Yamato Security's Windows forensic timeline tool. The source brief had it under Russia. That filing was wrong.

vision_pilot, with its AutoSpeed / AutoSteer / AutoDrive split, is still only a name in the brief. It is not a dependency.

Russia

What survives after the cluster is checked

The source brief grouped kernel inspection, binary work, OSINT scrapers, and threat hunting as a Russian specialty, then listed Hayabusa, sqlmap, redbpf, sniffglue, and rshijack beside two Russia-focused citations.

Hayabusa is Japanese and defensive. sqlmap is a global assessment tool. redbpf, sniffglue, and rshijack were not established as Russian, and connection-hijacking research is not part of this roadmap.

What remains, still cited rather than verified: a collection of OSINT utilities aimed at Russian public records, a UK-maintained matrix of Russian APT techniques, and an unconfirmed Windows anti-rootkit name, KSword. None of those is a robotics runtime.

Israel

The situational-awareness claim, narrowed

The brief assigned browser-native spatial intelligence and multi-feed command boards to Israeli engineering, and named gods-eye-view and IRONSIGHT.

gods-eye-view is real and is filed under Global. IRONSIGHT's path was corrupted in the source text and was not confirmed.

The capability still matters: a fleet needs a picture of where vehicles are and what the open sensors say. That picture is a software layer. This edition does not treat it as a verified national specialty.

South Korea

Hardware-in-the-loop, no named repository

The brief describes hardware-in-the-loop work on scaled platforms (F1Tenth-class vehicles and drive-by-wire development chassis), edge acceleration, and strict quality metrics.

No repository was named. This is a vector: look for HIL launchers, vehicle benches, and model-deployment tooling. Do not backfill a famous lab's name to make the cell look complete.

Albania

The brief describes telecommunication drivers, edge packet handling, and routing meant to keep telemetry alive on poor wireless links.

No repository was named. Treat it as a requirement — small messages, lossy links, command paths that degrade instead of stalling — and fill the cell when a specific project is found.

Four layers, only with pieces you can clone

01 · Integrity

Under the control loop, not inside it

Watch memory and privileges on the edge computer with mechanisms that do not sit on the control deadline. On Linux, that is eBPF-class tracing. On a Windows engineering station, use only a forensic tool whose publisher you have opened. KSword is a name in the brief, not a driver to load. Hayabusa belongs here as a log timeline after an incident, not as a real-time node.

02 · Transport

Zero-copy between perception processes

Agnocast is the verified way to hand ROS 2 messages across processes without a serialize-and-copy on the hot path. Nebula is the driver boundary in front of it. Point clouds and camera buffers should cross that boundary once. A cited Rust runtime (Horus) is not part of this layer until the repository is real.

03 · Perception and planning

Neural candidates, rule-based veto

Multi-camera detection of the Fast-BEV kind, still cited, proposes objects. AutoE2E, verified, proposes a trajectory without requiring an HD map. Autoware's behavior planner is the place those candidates are accepted or refused. When a map is present, the rule stack stays in charge. When the map is missing or stale, the handoff is to the map-optional model, not to an unreviewed network from an unread fork.

04 · Fleet picture

State leaves the vehicle in small messages

Telemetry has to survive a bad radio. That is a protocol requirement, which is all the Albania vector currently is. The display side is a globe or map that can show position, health, and open-source context. gods-eye-view is the verified example of the display. It is not a command link.

Design for the intake job

Translation without corrupting code

Stage 1

Discovery and a velocity score

A daily job queries GitHub and, where accounts exist, Gitee and GitFlic. It does not crawl the web at large. Filters are topic and language first, geography second, and geography only from what the host actually exposes.

  • Topics: robotics, autonomous vehicles, physical AI, ROS, kernel, forensics, networking.
  • Score from commits, pull requests, star growth, and issue activity over a short window. The threshold is a local choice, written down, not a magic number.
  • A high score puts a repository in a review queue. It does not auto-merge anything.

Stage 2

Translate text, leave the syntax tree alone

Machine translation of a whole file rewrites keywords and identifiers. The translator may only see comments, docstrings, and markdown.

  • Parse Python, C++, Rust, or Go with that language's parser.
  • Lift comments, docstrings, and docs/ Markdown out of the tree.
  • Translate those strings with a glossary for ROS 2, IEEE, and ISO terms.
  • Write the English back into the same nodes. Formatting, names, and indentation stay.

Stage 3

English documentation forks

A downstream mirror is for reading. It is not a claim of authorship. Licenses travel with the code. If the upstream license forbids a mirror, there is no mirror.

  • Webhook or a daily fetch on the upstream default branch.
  • Diff only markdown and the extracted docstrings.
  • Open a pull request on the English fork with the translation and a link to the upstream commit.
  • A person merges it. The bot does not push to main.

Stage 4

Interface index against the stack you already run

Embeddings are for search, not for a press release. Extract signatures you can actually diff: C++ headers, ROS interfaces, Python functions, HTTP routes.

  • Embed those signatures and compare them to Autoware, and to whatever else you really ship.
  • A daily note names the module, the upstream commit, the license, and whether the interface shape matches a driver you have.
  • Compatibility is a hypothesis until hardware-in-the-loop says otherwise.

Order of work

Three phases

Phase 1

Ingestion

API clients for GitHub, Gitee, and GitFlic with rate-limit handling. Store the raw snapshot, the commit list, and the metadata you scored. No translation yet. Geography filters only where the host provides them.

Phase 2

Translation and forks

Parsers for Python, C++, Rust, and Go. A glossary. An organization that holds English documentation forks. A bot that opens pull requests and stops there.

Phase 3

Index and the bench

Vector search over real interfaces. A daily note. Only then, and only for a module whose license allows it, a hardware-in-the-loop run. First candidates from this edition: Agnocast and AutoE2E. Not KSword. Not an unconfirmed dashboard.
